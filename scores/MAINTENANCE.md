# 国乐谱汇目录维护

站点目录由 `scores/data/works.json` 和 `scores/data/sources.json` 生成。定版下载使用已经校验过的 GitHub Release 附件。Space 的「国乐谱汇外部谱源与许可台账」保存原文件和出处，专门的翻谱台账记录校勘进度。

## 增加定版曲目

1. 登记可持续沿用的 ASCII 路径、曲名、版次、编制、实际分谱数量、署名和关键词。
2. 在翻谱台账核对实际发布文件、制谱版本、内容审查范围、版式，以及已有的排练证据。完成了哪一层，就填写哪一层。
3. 取得该版发布的依据。将合订本、简谱总谱和独立分谱包分列，登记实际页数或数量，以及对应 Release 链接。站点与公开提交只包含曲谱的公开信息和下载入口。口令通过已约定的途径提供。
4. 需要首页优先展示时填写 0 到 998 的排序值。999 表示只在谱库正文展示。
5. 用 `python3 scripts/build-score-site.py` 重建详情页、目录页和站点地图。保留旧版本记录，检查目录页和详情页的文件链接。

`scores/tools/rosters.json` 来自分谱的文件名。加新曲时按 `scores/tools/build_rosters.py` 的说明重建，确认乐器异名和兼奏记录，不把文件名中的声部当作已确认的到场人数。

曲目详情的分谱索引由同一文件目录生成，显示 ZIP 内的文件名和实际页数。改动别名、谱件或页数时，先重建乐器清单，再重建谱库。按乐器索引链接到每首曲目的文件筛选。

## 增加外部源谱

每个谱本记录原始来源、可公开的获取地址、版次、署名、文件页数、许可和适用范围。公版或开放许可的核对以具体谱本为单位。教育使用、付费租借及申请类条目保留其原站入口。现有 PDF 及压缩包通过私有备查入口归档。

## 发布后检查

- 验证站点地图只含能访问、有 canonical 的静态页面，`robots.txt` 指向根站点地图。
- 打开主页中文与英文入口，检查曲目详情、所列版本和下载是否一致。原有口令资料入口为 `/scores/archive/`。
- 用自适应编配的演示导入，在席位不足和音域不合适时检查输出，再以实际乐团的自有 MusicXML 试奏复核。
- 商业授权、订单、试奏申请及真实成交数据由独立流程承接。
