# 国乐谱汇维护与发布

公开站地址为 <https://taitai2025.github.io/scores/>。此仓库维护公开目录、版本信息、原机构谱源和浏览器内编制工具。私有管理系统中的联系人、合同、订单、授权文件及内部校勘材料，不随公开站构建。Release 附件的既有公开入口保持可追溯，PDF 口令通过原约定途径提供。

## 数据与页面在哪里修改

| 内容 | 维护入口 | 生成或引用结果 |
| --- | --- | --- |
| 曲目、编制、版次、署名、质量说明、发布依据 | `scores/data/works.json` | 曲目详情、目录、检索与编制入口 |
| 既有下载文件及旧入口兼容 | `scores/catalog.js` | `scores/archive/`；应与 works.json 的版本和附件保持一致 |
| ZIP 内分谱文件名与实际页数 | `scores/parts-index.js` | 逐曲声部文件索引 |
| 声部别名、兼奏、可选及备用规则 | `scores/tools/build_rosters.py` | `scores/tools/rosters.json` |
| 具体开放谱本与官方资源入口 | `scores/data/sources.json` | 免费谱库与总谱导航 |
| 公共页面模板 | `scripts/build-score-site.py`、`scripts/score_experience.py` | 静态 HTML、公开检索索引和地图 |
| 整曲、分段试配 | `scores/tools/arrange/` | 浏览器内 MusicXML/MXL 导入、席位与换页分析 |
| 独立检查 | `scripts/verify-score-site.py`、`scripts/check-score-discovery.py`、`scripts/test-score-turn-scope.mjs` | 离线一致性及可选上线检查 |

不要只改生成的曲目 HTML；下次构建会覆盖。新增文件索引不等于音乐内容已校勘。声部索引来自实际文件名，不能据此推断每个乐章的到场人数或确认可兼奏。

## 构建与检查

运行环境为 Python 3.10+、Node.js 22+。谱库构建与检查只用标准库，无须安装 Python 包，也不联系外部源站。个人主页构建需要 `package.json` 已声明的 jsdom。

```sh
# 首次构建个人主页时安装其现有依赖
npm install

# 完整构建：个人主页先生成，谱库后生成并合并地图
npm run build

# 仅修改谱库时
npm run build:scores
npm run check:scores

# 安装现有 jsdom 后，复验选曲单的浏览器行为
npm run check:scores:ui
```

`build:profile` 仅生成个人主页，会重写根 `sitemap.xml`。正式发布前仍运行 `build:scores`，使根地图与独立 `/scores/sitemap.xml` 一致。`robots.txt` 同时声明这两份地图，避免个人主页单独维护影响谱库发现。不要把构建日期或文件时间戳当作实际发布日期。

`check:scores` 检查目录 ID 一致性、附件数量与分谱数、明确的公开字段、HTTPS 下载地址、静态页面/脚本/样式/字体引用、内部锚点、重复 HTML ID、地图及 canonical、明显的凭据泄漏，以及检索、席位、项目恢复、可选声部比较和换页回归案例。`check:scores:ui` 额外使用 jsdom 验证选曲单的保存、导入导出等交互。错误消息不显示检出的密钥值。这些检查不下载大文件，不证明音乐逐音准确、权利完整、搜索已收录或网站已上线。

新增公开数据字段时，先确认公开用途，再在 `verify-score-site.py` 对应允许名单中登记。不要将私有数据库原样序列化到页面。支付密钥、PDF 密码、合同全文、联系人资料、临时签名 URL 和私有对象键不得放入公开 JSON、源码或 Git 提交。

`.github/workflows/score-validation.yml` 在谱库相关路径更新时执行只读检查、重建一致性与语法检查。校验步骤不请求外部谱源，不发布网站，不写仓库。工作流本身由 GitHub 托管运行，首次启用按仓库的 Actions 设置处理。CI 成功与 GitHub Pages 部署成功是两个独立状态。

## 增加或修订曲目

1. 沿用稳定 ASCII slug；不要为改标题更换 URL。署名未知时可留空，在公开界面显示待核实，不猜测作者。
2. 在翻谱台账匹配实际文件、版本、内容校勘范围、版式与排练证据。文件存在、可打开、内容复核和实际排练分别记录；历史版本名中的“终版”不能代替当前验收证据。
3. 记录该版本的发布依据及实际许可范围。翻谱版本的权利说明不能自动替代原作品、改编、录音或商用许可。
4. 将合订本、指挥总谱与独立分谱 ZIP 分开登记，记录真实页数/文件数、字节数和具体 Release URL；有 SHA-256 时保存它。同步 `catalog.js`，原附件不静默覆盖。
5. 更新实际分谱文件索引；兼奏、备用、可选与不确定乐器保持显式。首页排序值为 0–998，999 不进入重点推荐。
6. 运行 `build:scores`、`check:scores`。在电脑与手机核对有/无结果搜索、至少一份大套谱详情、不同简谱版本、官方链接与文件下载。

删除或撤下曲目时，同时处理数据、生成的旧详情页、旧索引和地图；不要留下仍能被发现的旧入口。已发布附件的撤下按具体授权和用户既有使用范围单独处理。`robots.txt` 不能撤销下载权限。

## 外部谱源

以具体谱本记录版次、编制、署名、页数、来源、许可和下载方式。登记申请、付费、租借、样张与完整下载分别描述，不把免费访问等同于可转售。保留原机构入口，不复制上传未获准公开的文件。维护时抽查高频外链并记录实际核查日期；短时不可访问先标为待复查，不自动判断永久失效。

## 隔离开发与发布

在最新远端的独立分支工作。多人同时开发时，约定每人独占文件；数据与模板修改完成后由一人执行最终生成、检查、提交及发布。不要全目录覆盖远端，不要 force-push，不将别的会话未完成的科研或网站改动一起提交。

离线准备可复核增量包：

```sh
python3 scripts/prepare-score-release.py --base <已核对的远端提交SHA> --output <仓库外的目录>
```

脚本使用临时 Git index，保留真实暂存区，执行离线检查与语法检查；按路径允许名单生成 `upload/`、二进制兼容补丁、变更/删除清单及 SHA-256。所有上传文件来自同一 Git 快照；打包期间源码变化会拒绝生成。包内只标记 `prepared`，不会写“已上线”。超出谱库范围的变更会阻止打包，先拆分，不为通过检查扩大至整个工作区。

通过 GitHub 网页提交时，按 `upload/` 内的相对路径放置文件；不要把 ZIP 直接上传充当部署，也不要遗漏 manifest 中的删除项。先核对最新远端与包的基线；出现新提交则合并、重建、重测。保留实际提交 SHA 和 GitHub Pages 的部署记录。

### 上线核验与回退

1. 等待 GitHub Pages 对应提交的部署状态成功。
2. 运行 `npm run check:scores:live`，检查实际 HTTP 200、canonical、地图和个人主页入口。
3. 人工核对首页、搜索、曲目详情、开放谱源、选曲单、编制工具、手机排版和真实文件获取。成功下载与按钮能点击分别记录。
4. 记录“提交 SHA / 部署 URL / 部署结果 / 核验北京时间 / 核验范围 / 遗留问题”。源代码完成、已提交、已部署与线上核验分别标记，不以本地通过替代生产证据。
5. 若有回归，撤销本次明确提交，让 Pages 正常重新部署上一可用内容；不要改写分支历史。验证回退版本及地图，后续修复在新提交中完成。

## 搜索控制台的人工验证

静态 HTML、独立标题/描述、canonical、内部链接与 sitemap 是代码准备工作。实际收录和排名由搜索平台决定。

| 平台 | 拥有者操作 | 需要保留的证据 |
| --- | --- | --- |
| Google Search Console | 验证对应站点属性，提交 `/scores/sitemap.xml`，检查首页与三至五个曲目 URL | 属性、验证方式、地图处理状态、索引状态与日期 |
| Bing Webmaster Tools | 验证站点并提交谱库地图；按真实回执记录 IndexNow 状态 | 提交回执、实际抓取/索引状态，分别记录 |
| 百度搜索资源平台 | 使用拥有者账号验证站点，查看当前可用提交方式并提交具体 URL | 平台实际接受结果、抓取错误及收录信息 |

账号验证文件或 meta 标签必须来自该账号的真实配置，不伪造验证码。IndexNow 接受通知不等于搜索收录。控制台尚未接入时明确“待验证”，不展示编造的流量、用户数、热度排名或高校评价。

## 长期维护边界

每次增量发布保存可恢复的 Git 提交和检查范围。重大错音、缺页、误版和不适用链接先处理；完整排练体验依赖团体反馈。高校试用、支付、订单、开票、投稿分成和期限下载，由具备相应权限的独立服务承接。公开站不提供伪装成真实交易的按钮。私有台账 JSON 导出只含附件引用时，必须说明它不是附件文件的完整备份。

## 单份分谱在线查看

在 GitHub Actions 运行分谱发布流程。它读取已发布的 ZIP，仅复制符合目录、页数和打开口令校验的 PDF，将原始加密字节写入 `score-pdf-files` 分支并生成索引。个人主页的「打开 PDF」会根据索引显示，合订本和原 ZIP 入口照常可用。浏览器的 PDF 阅读器会处理打开口令。

新增或更换版本时，先发布受保护的附件并更新可核实的目录字段，再运行分谱发布。路径包含对应 ZIP 的 SHA-256 前缀。回滚网站目录时，可保留旧路径及 Release；必要时重新运行所恢复版本的分谱发布。
